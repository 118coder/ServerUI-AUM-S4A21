# 第一部分 · v2.1 更新记录

> 自 2.034 以来的全部功能变更与修复。本部分面向使用与交付；维护细节（仓库/令牌/排障）见《ServerUI-维护参考》。

## 一、DLL 扩展页重构（与游戏启动器同源机制对齐）

### 1. 「应用更改」只直写 GameGaurd.ini
- 不再每次解压补丁包：点击「应用更改」只把当前勾选状态**直写**游戏根目录 `GameGaurd.ini` 的 `[Plugins]` 列表；
- 规则：勾选的受管插件 → 条目保留/新增；取消勾选 → 条目从列表移除（文件保留）；原有非受管插件（如 S4A21MemOpt.dll）、自定义扩展与注释全部保留；
- 游戏根目录未发现挂载器（GameGaurd.dll / az.dll）时，应用前会提示先执行【新DLL安装】。

### 2. 新增「新DLL安装」（设置与关于页）
- 原「待定2」按钮 → **「新DLL安装」**（绿色，下载图标）；
- 功能：把 `实用工具包\DLL覆盖\客户端补丁.zip` **完整安装**到游戏根目录：
  1. 复制全部补丁文件（挂载器 GameGaurd.dll / az.dll / 插件 DLL / 配置 ini / EquipmentSwap 界面等）；
  2. 已编辑过的插件配置 ini **保留不覆盖**（恢复默认模板 = 删除游戏根目录对应 ini 后重新安装）；
  3. 合并 `GameGaurd.ini [Plugins]`（受管插件默认全部启用）；
- 安装成功后切换回【DLL扩展】页立即显示插件列表。

### 3. 未安装时不再误显示"已安装插件"
- 新增安装判定：游戏根目录存在 **GameGaurd.dll / az.dll**，或 `GameGaurd.ini` 已有插件记录 → 视为已安装；
- **未安装时**：【DLL扩展】页只显示「—— 未安装 DLL 扩展 ——」引导空态（不渲染任何插件行），插件开关全部置灰，状态行提示"请先点击【新DLL安装】"，「添加扩展 / 删除扩展」也会被拦截并引导先安装。

### 4. 自定义扩展支持 DLL / INI（与启动器一致）
- 启动器插件列表（同一个 `[Plugins]` 节）按顺序加载，条目**可以是 DLL 或 INI**，路径 = 从游戏根目录按文件名加载；
- 本页「添加扩展」文件选择过滤器改为 `*.dll;*.ini`，相关文案统一为"扩展"（添加扩展 / 删除扩展 / 自定义扩展）；
- 第三方插件（如 S4A21MemOpt.dll）**不设"内置/自带"限制**：与其它非受管插件一样归入自定义扩展，可由玩家自由添加/删除/停用（原先的"禁止手动重复添加"拦截已移除）。

### 5. 配置 ini 可视化编辑器的分组管理
- 顶部「添加分组」：输入节名新建分组（不能含 `[ ]`、不能与已有分组重名）；
- 分组标题行：**「+ 添加键」**（分组内添加键：键名不能含 `=`、不可重名，按值类型自动显示开关/数字/文本框）、**「删除分组」**（红色，整节移除）；
- 键行行尾「删除」：移除单个键；文件开头无节名的键自动归入「(主配置)」分组（可添加键、不可删除分组）；
- 分组/键任何增删后，窗口标题显示「（已修改，保存后写入）」；
- 保存时保留原文件编码与未编辑内容（注释、节顺序、值原写法），新建文件用 UTF-8。

## 三、更新日志获取修复（ps1核心\update.ps1）

- 症状：服务端本体能更到最新，但「更新日志.txt」日期不更新；删除旧日志后才能获取；
- 根因 1：提交记录 API 偶发返回 200 但空数组 `[]` 时，旧逻辑把已缓存的历史提交**全部丢弃**；
- 根因 2：镜像日志此前**整文件覆盖**本地日志，旧版本日期被保留；
- 修复：空响应时**保留已有缓存**；镜像日志只作为**提交历史数据源并入**（去重合并提交段，不再覆盖整文件）；效果 = 最终日志始终由本次生成，版本头/更新时间**恒为本次日期**。

## 四、编码事故修复：update.ps1 的 UTF-8 BOM（必修）

- 现象：启动更新流程即打印一串 PowerShell 解析错误（意外的 `)`/`}`、数组索引表达式丢失、变量引用无效），随后「本次未检测到服务端源码文件变更」，更新完全不执行；
- 根因：update.ps1 的 **UTF-8 BOM 丢失**；Windows PowerShell 5.1 对无 BOM 文件按 ANSI(GBK) 解码，中文注释字节被误读为引号/括号等语法字符 → 一串假解析错误；
- 修复：写回 UTF-8 BOM（内容不变），并用 PowerShell 5.1 引擎验证 0 错误；
- 规则：ps1 一律保持 UTF-8 带 BOM；编辑后必须校验 BOM 并用 5.1 引擎验证。

# 第二部分 · 安装位置与目录结构

## 一句话

把 `ServerUI-*.exe` 放到【游戏根目录】（和 `DNF.exe` 同一级），解压出的【AUM管理组件】文件夹也放在同一层。

## 示例目录

```
游戏根目录  E:\Game\S4A21_CN\            ← 你放 DNF.exe 的那一层
├── DNF.exe                          ← 游戏主程序
├── ServerUI-有依赖版.exe             ← AUM 管理器（需系统已装 .NET 10 运行时）
├── ServerUI-无依赖版.exe             ← AUM 管理器（免安装，自包含运行时）
├── ServerUI-兼容模式.exe             ← AUM 管理器（Win7/net48，附 .exe.config）
└── AUM管理组件\                     ← 所有配套内容都在这层文件夹
    ├── ServerUI\                    ← 管理器 C# 源码（更新AUM时会重新编译）
    ├── ps1核心\                     ← 核心脚本（update / 更新AUM / 进行本地编译 / gmtool / save-* 等）
    ├── latest\                      ← 本地缓存包（断网兜底更新用）
    ├── ServerS4A21-AUM\             ← 服务端源码 / 运行目录
    │   └── dist\win-x64\            ← 编译产物/运行目录（DfoServer.exe、Data\）
    ├── dfogmtool\                   ← GM 工具源码；publish\DfoGmTool.exe 为成品
    ├── DX11补丁\ / DX12补丁\        ← 可选渲染补丁（各含"无水印"子目录）
    ├── dotnet-sdk\                  ← 便携 .NET SDK（可选）
    ├── 实用工具包\                  ← 客户端补丁 zip / 安全 DLL 等
    ├── 存档管理\                    ← 切换库（你保存的存档）+ 备份存档
    └── *.bat / *.txt / *.md         ← 快捷入口与说明（开始更新/启动本地游戏/快速换挡等）
```

## 关键路径速查

| 用途 | 路径 |
|------|------|
| 管理器主程序 | `<游戏根>\ServerUI-*.exe` |
| 更新日志 | `<游戏根>\AUM管理组件\更新日志.txt` |
| 服务端运行 | `AUM管理组件\ServerS4A21-AUM\dist\win-x64\DfoServer.exe` |
| 主存档数据库 | `…\dist\win-x64\Data\inventory.db` |
| PVF 资源脚本 | `…\dist\win-x64\Data\Pvf\Script.pvf` |
| GM 工具 | `…\dfogmtool\publish\DfoGmTool.exe`（页面 http://localhost:5051） |
| 服务端启动脚本 | `…\ServerS4A21-AUM\start-server.bat` |
| 客户端补丁包 | `实用工具包\DLL覆盖\客户端补丁.zip`（安装到游戏根目录） |

## 不知道解压到哪？

1. 把压缩包里释放出的 `ServerUI-*.exe` 放到【DNF.exe 同一层】；
2. 同一个位置放【AUM管理组件】文件夹；
3. 双击 `ServerUI-有依赖版.exe`（或免安装的 `无依赖版.exe`）；
4. 程序启动后自动检测 DNF.exe 并提示；AUM 自动定位自己的 AUM管理组件 目录，无需手动指定。

> S4A12 已停止维护，以上均为 S4A21 版本结构。
